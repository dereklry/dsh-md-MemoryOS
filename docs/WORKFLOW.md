# dsh-md-MemoryOS 使用流程（从你发一句话，到收工归档）

> 使用者视角。读完要能回答三件事：**本 OS 的功能定位**、**没做到的我该改哪里**、**我怎么知道它真的在跑**。
> 代码契约＝`DESIGN.md`；模型侧规则＝`AGENT-GUIDE.md`；取舍理由＝`JUDGMENTS.md`。

---

## 0. 这套 OS 的定位（先读这段，再决定要不要装）

### 0.1 它管什么

管理**用户自己定义的文件夹下的 `.md` 文件**。

### 0.2 它不管什么：资料自带的层级索引

`.md` 文件本身应当自带层级索引，例如这样一条链：

```
agents.md（入口·指引 LLM 去读哪本手册）
   └─ handbook.md（本机资料总体情况：有哪些 code 项目、处理过的事务，归档在哪）
        └─ 各个归档 md（一件事一份，写清楚过程与坑）
             ↑ LLM 按索引逐级追查，找到回答本次问题所需要的那份资料
```

**这条索引链与 OS 的功能无关，但它正是"md 能无限扩展还查得准"的关键能力**——OS 替代不了它，只加速它。

### 0.3 那 OS 的能力在哪

在于**通过 Jev 判路、`md_ledger_light` 这类"把资料插进上下文"的能力、以及提供可用工具**这三条路，达到**加快流程、节省费用**的效果。换句话说：索引链负责"找得到"，OS 负责"不用每次自己找、也不该找的都来找一遍"。

### 0.4 什么时候不建议用

- **md 文档在 5 个以内**：不建议用本 OS，直接让 LLM 读目录更省事。
- **你已经遇到"md 太多、LLM 索引路径太长"的问题**：这时候加载它才有收益。
- 当前版本仍有不完善之处，能力有限。不满意的地方，可以等后续版本，也可以直接要求你自己的 LLM 取源码修改（源码就在 `docs/` 之外那几个文件里）。

### 0.5 归档 md 的格式建议（配合 OS 用）

1. **每个事项形成 1 个独立 md 文件**，并在 `handbook.md` 里记下指针与指引。
2. 每份 md 内部应有完整描述：**本事项说明 · 使用的概念 · 流程 · 遇到并处理过的坑**。
3. 归档即成为可追寻的记忆：事情做完后**无需再 recall 会话内容**，也就不会被当时那些绕坑的噪音再次带进来。建议使用自定义skill完成归档动作。
4. 建议**用 git 管理这些 md**——但请用 git 时特别注意：**别让私人信息上传到共享 GitHub，那是永久不可磨灭的泄密**。本 OS 在这条上有一道守卫：明文 Key 落在 git 工作树内会被直接拒写（见 §6）。
5. **格式契约（照写就行，工具顺着它读，不需要你迁就工具）**：
   - 条目标题写成 `### AA17 <情形>：<动作/结论>` 一句人话，紧跟一行 `- **触发**：用户会怎么说这件事`（症状词、口语、简称、错字都塞进触发行——它是"以后还能不能搜到"的关键）。
   - 专档开头（前 12 行内）写一行 `> 档位：叶子 ｜ 指针条目=AA17`：**叶子**＝默认，**中枢**＝指路文件（如 handbook 本身）。回指的条目号必须真实存在。
   - 目录索引表里用**标准 Markdown 链接** `[事项名](事项.md)` 登记新档——这是"这份资料有没有人引用过"的判据。
   - 确属一次性别档、不值得登记 ⇒ 文件头写 `> 归档：免索引（理由）`（会被列进豁免清单，可见）。
   - **准备 `git commit` 前**让模型跑一次 `memoryos_graph(action='archive-check')`：它只看"本次未提交的新增"，把"新档没人引用／回指条目号悬空／新条目没人回指"标出来，**只报事实、不改文件、不挡提交**。

### 0.6 「Jev 判路问句文档」是什么（回路图里 ②⑤⑥ 都会提到它）

一份**给判定模型看的选项表**，每行一个资料项，三列：

| 列 | 含义 | 写法要求 |
|---|---|---|
| `id` | 资料项标识（指向哪个文件/条目/主题） | 稳定、可 grep；别用会改的编号 |
| `criteria` | **判据**：什么情况下该把这条资料亮出来 | 用**用户会说的话**写（含口语别名），不要写成术语缩写——判定模型按字面读 |
| `hint` | 亮出时附的一句指引：什么情形、做什么、去哪看正文 | 空白模型看一眼就能照做；禁写绝对行号（一改就漂移） |

它不是一份说明文档，而是 **② 的全部输入**：模型每回合就在这份表的 `criteria` 里选，选不中就没有任何资料被亮出来。所以它必须与资料**同步维护**（见 §1 的 ⑤⑥ 与 §8 体检）。

> 本仓库当前**还没有这份文档的实现**（亮起功能未搬入，见「本版本跑到哪」）。等你自己的实例落地时，它通常是一份 markdown 表 ＋ 一份 jsonl 判路战绩。
> **⚠ 2026-10-02 追加**：`radar` 已**降级为默认不开启**（出厂 `default:false`）——所以本文这份问句文档在当前版本里**不是必做项**；只有当你要显式 opt-in 开语义亮起时，它才变成"必须同步维护"的输入。为什么降级＝`JUDGMENTS.md` §5.5。

---

> **本版本（v0.4.0）跑到哪**：新装未改配置时，概览页应是 `生效中 5`（面板、状态体检、开关账本、资料面管理、**指针图＋提交前归档闸**）＋ `已关 1`（语义引擎：**按需调用的工具，不是主力**）＋ `未实现 5`（亮起的旧形态／按需语义寻路／建档／候选／定时维护）——其中 **`radar`（每回合自动指路）自 2026-10-02 起出厂默认就是关的**（降级，非"欠着没做"；见 `JUDGMENTS.md` §5.5），**语义能力改走"按需工具"**（`find` 未实现＋`jev-engine` 配好备用）。
> 回路里 **②⑥ 两格的自动部分还是灰的**（③ 的"查资料在哪"、④⑤ 的"范围边界＋提交前归档检查"已经能用）：形状先看清，别按"它已经在替我亮资料"来期待。

**读法**：②③ 是"用得上的部分"，④⑤⑥ 是"越用越准的部分"。本版本先把**边界与控制权**做实（资料面＋开关＋三本账＋四个工具），再把器官一件件搬进来。顺序反不得：范围没划清就建索引、就每回合花钱亮起，等于在错的地基上装马达。

### 1.5 回路背后的三条硬规定

**② 的判定质量不是玄学，是三份数据的函数**：③ 读到的资料、资料面 ⑤② 划的范围、⑤③ 维护的判路问句文档。三者任一分叉，② 都会**变哑或变歪，并且不报错**。所以：

1. **② 每回合一次判定调用＝全系统唯一的常态计费点**。它贵不是问题，**白贵才是问题**——判路问句文档过期 ⇒ 花着钱亮错资料，比不亮更亏。
2. **⑤ 归档必须同步 Jev 判路问句文档**（加项 / 改 criteria / 摘行）。资料与问句的分叉是**静默失灵**：面板上 radar 显示"生效中"，② 却永远选不中新资料——你以为它在帮你找。
3. **⑥ 体检要同时盯指针图和判路问句文档**，且"新增事项类别"当天就该跑一次（不必等周期任务）。

分叉三种症状（都**不报错**，只能靠体检发现）：

| 症状 | 现象 | 根因 | 处理 |
|---|---|---|---|
| **漏亮** | 新资料从来没出现在亮起结果里 | 加了资料、没加问句项 | ⑤③ 补一项（`id`＋用用户会说的话写 `criteria`＋`hint`） |
| **错亮** | 注入的条目与实际话题不相干 | `criteria` 还是旧说法／口语别名缺失 | ⑤③ 改该判据（加别名，删过时描述）；**过期比缺失更坏，拿不准就删行** |
| **假工作** | 亮起一直"生效中"，却长期只弃权或注入从没被引用 | 资料结构变了（改名、拆分、搬目录）而文档没跟上；或范围划得太宽 | 跑一次体检；核对 `hint` 指向的路径还在；不在就修或摘 |

## 2. 首次启动（十分钟内）

1. **装**：把本包列进 profile 的 `bundles`（或用插件管理器装），按 §3 改配置，然后**重启 DSH**（插件不能重启自己）。
2. **认面板**：设置 → 侧栏出现「**记忆系统**」，五个页签：功能开关｜资料面｜概览｜依赖与路径｜账本。
3. **划边界**：去「**资料面**」把要管的目录纳入管理（§4）。**先做这步**——后面每个器官都吃这个集合；没有范围，检索、亮起、候选全是空转。
4. **建图**：同一页点「**建立指针图**」（或让模型 `memoryos_graph(action=build)`）。秒级完成，页面立刻显示节点／边／文件数。**没建图时「指针图」显示"待配置"，不算生效。**
5. **看体检**：「依赖与路径」四个探针一眼看清（数据面／记忆根／指针图／内核）。缺"硬"的那格会把对应功能直接标 `不可用`；图过期只算"降级"（还能查旧的）。
6. **（可选）接语义引擎**：走 §5。接上之后亮起／候选这类器官才谈得上语义档；不接也能用图（图是纯本地词法，零账）。
7. **让模型认路**：把 `AGENT-GUIDE.md` §8 那块指令粘进你的 `AGENTS.md`／preset，模型才会主动读状态、主动建图，而不是猜。

**装成功的判据（别信日志）**：宿主工具表出现 `memoryos_status`／`memoryos_switch`／`memoryos_setup`／`memoryos_surface`／`memoryos_graph` 五个；设置里有「记忆系统」；面板刷得出数据。

## 3. 配置只有一处：profile

在 profile 的 `cordis.patch.yml` 本包那一行下改（全部可缺省）：

| 想干什么 | 改哪个键 |
|---|---|
| 划**基线**资料范围（多个用 `;` 分隔） | `memoryRoot` |
| 账本与派生数据落点 | `dataDir` |
| 指定 Python（读面纯标准库，系统 Python 就够，不必建 venv） | `pythonBin` 或 `kernelRepo` |
| 禁止模型改开关／禁止代存 Key | `llmCanSwitch: false`／`modelCanSaveKey: false` |
| 测通上游、超时、新鲜度 | `baseUrl`／`model`／`probeTimeoutMs`／`setupFreshDays` |
| 资料面每根扫到多少就停 | `scanCap`（默认 400） |
| 图水位超过几小时算"该重建" | `graphStaleHours`（默认 24） |
| 建图规模上限 | `graphMaxFiles`（默认 2000 份）／`graphMaxBytes`（单份默认 1.5MB） |
| 某功能的出厂默认 | `defaults:` 下对应键 |

优先级一句话：**面板／工具切出来的账本 ＞ profile 默认 ＞ 出厂默认**。长期改就动 profile（要重启），临时改就在面板点（**热生效不重启**）。

> `memoryRoot` 与面板「资料面」加的目录是**并集**；基线在面板上是**只读一行**——插件不代写宿主配置。

## 4. 资料面：管到哪、排到哪（本版本新增，live）

### 4.1 看

页顶三个数：**几个目录**在范围内（不存在的标红）、**纳管多少个 `.md`**、**被排除多少个**。下面每个目录一行：

- **来源**：`profile 基线`（不可在此删）／`面板加`／`模型加`（可移除，带添加时间）；
- **纳管数**：扫到多少 `.md`（带 `+` 表示命中 `scanCap` 上限——**只数文件名，不读内容**）；
- **被挡数＋归因**：不给笼统总数，而是"哪条规则挡了几个"；
- **样本路径**：前几条相对路径，用来确认"扫的真是我以为的那批"。

文件类型固定 `.md` 是**有意的**：页面给提示而不是输入框。加后缀容易，让检索真管它是另一回事（要扩就让 LLM 按 `DESIGN.md` 改，或等后续版本）。

### 4.3 指针图（同页第二个卡片）

范围划好点「**建立指针图**」：它扫管理范围内的 `.md`，只索引**标题·条目号·触发行·反引号路径·「§三 XX12」式指针**（正文不进图 ⇒ 图小、建得快、也不会把敏感正文另存一份）。卡片显示：节点数／边数／扫了几份／**上次建图后又改了几份**／未解析引用几条。

- **改了资料就再建一次**（秒级、幂等：同一批文件必然得到同一张图）。超过 `graphStaleHours`（默认 24h）或有文件改动未入图 ⇒ 标"该重建"。
- 想问"这个词牵动哪些文件"⇒ 让模型跑 `memoryos_graph(action=light, query=…)`（**一次都没有命中时，它会顺手扫一遍管理范围内的正文**，告诉你"这个词在哪个文件的哪一行字面出现过"；扫完一个都没有，也会如实说"已扫 N 份、零命中"）；想知道"哪里有洞"⇒ `action=check`。
- **图是派生缓存**：`<dataDir>/graph.json` 删了可重建，不参与备份与迁移。
- 查回来的话术会标 **精准** 还是 **变体**（变体＝归一子串／删一字／词相似度≥0.8 兜底）。看见"变体"就知道它是在猜，别当命中。

### 4.2 改

| 动作 | 写法／操作 | 系统的反应 |
|---|---|---|
| 纳入一个目录 | 输入路径 → 「纳入管理」 | 写一行 `add-root`，**立刻**进快照与探针（不重启） |
| 移出 | 该行「移除」 | 写 `drop-root`（谁加的、何时加的仍在账上） |
| 排除某个子目录 | 规则写 `notes/drafts/` | **先试算后落账**：一个文件都挡不到 ⇒ 拒绝并说"多半路径写错"，不留下"以为排除了"的错觉 |
| 排除某个文件 | `todo.md`（任意层级同名） | 同上；规则行显示"挡了 N 个" |
| 排除某类命名 | `*.draft.md` | 同上 |
| 排除跨层子树 | `archive/**` | 同上 |
| 取消排除 | 规则行「解除」 | 计数复原，账上多一行 `drop-exclude` |

匹配是**双口径**：既按"相对某个记忆根的路径"，也按绝对路径。`drafts/` 与 `drafts-old/` 是两回事（按路径段边界比较，不做字符串糊弄）。

两条硬边界：**`*`／`**`／去掉通配符后不足 3 字符的规则一律拒**（那等于悄悄清空资料面）；**profile 基线删不掉**。每次改动落 `surface.jsonl` 一行（`op / path或pattern / by / reason / ts`），**被拒的操作不进账**——账本里只记真发生过的事。

## 5. 配置型功能：为什么没有开关（以语义引擎为例）

它的"打开"是一串动作：

```
① Jev Key 到位   —— 该你（或你明确委托模型代存）
② API 测通       —— 该模型：memoryos_setup(action=probe) 真发一次极小请求
③ 生效           —— 前两步都完成，状态才从「待配置」变「生效中」
```

所以这类功能**面板不给开关**，只给状态与待办清单（还差哪一步、这步归谁、怎么做）。你可以点「**接管**」锁成自己说了算（模型再动被拒，理由回给它），「解除接管」还权。

对话里说一句就够："把语义引擎接上，Key 我放好了，你测一次通就打开。"

**测通有保质期**（默认 7 天）：过期自动回退成「待配置」，重测一次即可，不用你记着。**为什么值得这么绕**：没测通就显示"生效中"是骗人——它每回合白烧账而什么都没干。

---

## 6. Key 放哪（一条建议，一道守卫）

**建议：存进宿主凭据面，ref 用 `JEV_API_KEY`。** 它物理上在 `~/.dsh/.credentials.yaml`：

1. **不在任何 git 工作树里** ⇒ 不存在"忘了 ignore 就被推上 GitHub"；
2. **在用户目录** ⇒ 不随 app 升级覆盖（升级替换的是安装目录与 profile 组合）；
3. 提供方以 **收紧权限 ＋ 原子替换 ＋ 文件锁** 写它；面板问"配了没有"时**不必读明文**。

退到文件时有守卫：**目标落在某个 `.git` 工作树内直接拒写**（除非显式开 `allowKeyInRepo`／`allow_in_repo`，且界面会标红）。明文 Key 永不进账本、日志、快照或工具返回值，只出现掩码。旧位置可配进 `legacyKeyFiles` 只读兼容，但每次都会标警催你搬家。

## 7. 日常：三种动作分别在哪做

| 你想… | 去哪 | 会发生什么 |
|---|---|---|
| 看现在什么在跑、为什么没跑 | 功能开关页 | 每行：状态／谁能操作／谁定的＋理由＋时间／成本／缺哪个依赖／差哪一步 |
| 划或改资料范围 | 资料面页 | 写一行账，热生效；计数与归因立刻变 |
| 关掉某项（嫌它每回合花钱） | 该行「关」 | 写一行账，热生效；概览统计立刻变 |
| 让模型做需要动作的启用 | 在对话里说 | 它调 `setup`／`switch`；账本页留下"模型·理由·时间" |
| 某功能被模型反复开关，想收权 | 该行「接管」 | 写 `lock:true`，模型再动被拒；「解除接管」还权 |

「接管」是这页最重要的安全阀：默认有些事交给模型，但你随时可以说"这件事以后我定"。

## 8. 怎么判断它健康（以及什么不是故障）

- **`待配置`、`降级` 是正常工作状态**，不是坏——它们在说实话（比假装"生效中"诚实得多）。
- 「依赖与路径」四探针一眼看到缺什么、去哪改。
- 「账本」三本账（开关／配置／资料面）让任何一次改动都能回答"谁、何时、为什么"。
- 账本**坏行数**会被计数并跳过（面板显示"坏行 N"）。不为零就去查那本 jsonl，别等它长成大坑。
- 扫描计数带 `+` ＝ 命中 `scanCap` 上限，只表示"至少这么多"，不是错误。

## 9. 出问题了按这个顺序查

| 症状 | 先查 | 常见原因 |
|---|---|---|
| 设置里没有「记忆系统」 | profile `bundles` 含本包了吗；`Tool.listTools` 有四个工具吗 | 没装进 profile／没重启／装载契约漏项（**静默无日志**） |
| 面板在但"没有数据" | 这个 profile 有 webServer 吗 | headless 属预期：面板无数据面，其余功能照常 |
| 某功能 `不可用` | 依赖与路径页缺的硬依赖 | 记忆根没划／找不到 Python |
| 某功能 `降级` | 同一页的可降级项 | 图水位过期；没 Key（语义档退回本地词法） |
| 某功能一直 `待配置` | 该行待办写着谁做 | 归你的（Key）；归模型的让它 `probe` |
| 加了目录但计数是 0 | 该行是否被标"不存在"；样本路径对不对 | 路径写错；或那批 `.md` 真被某条排除规则挡着 |
| 加了排除规则却没变化 | 规则行"挡了几个"；是否根本没落账 | 试算挡不到 ⇒ 被拒（故意的）；`drafts/` ≠ `drafts-old/` |
| 想管的类型不是 `.md` | —— | 本版本固定：让 LLM 按 `DESIGN.md` 扩，或等后续版本 |
| 图显示"该重建" | 资料面页图卡片的 changed 数 | 改了资料没重建：新资料不进图，索引就看不见它 |
| light 查不到刚写的条目 | ① 该条目有没有 `- **触发**：` 行（**触发行是索引唯一认的东西**，跑 `memoryos_graph(action=check)` 看缺哪些）；② 如果只是"词在正文里、没进过图"，`light` 的**零命中兜底会直接报它在哪一行**——先看那一段 | 补触发行（别改标题）；兜底只报字面位置，不替下结论 |
| light 回复里出现"变体" | 输出的解析级别 | 说明词形没对上：要么补触发行/别名，要么这个查询本来就该写条目号 |
| 模型说"开不了" | 让它把 `✗ 拒绝：…` 原文念出来 | 仅用户可切／已被你接管／未实现——都是设计不是故障 |
| 想彻底回到默认 | 删 `<dataDir>/switches.jsonl`（资料面同理 `surface.jsonl`） | 账本是唯一改动来源；**注意这会丢掉可追溯性，先备份** |

## 10. 升级与回滚

- 升级前：存一份 `Tool.listTools` 清单；备份 profile 三件（`package.json`／`cordis.patch.yml`／`pnpm-lock.yaml`）。
- 代码回滚＝本仓 `git revert`；配置回滚＝还原 profile 三件；三本账纯追加，留着不阻碍回滚。
- 界面跟随宿主主题（颜色只用主题 token，light/dark 都验过）：token 改名最坏是外观降级，不会白屏。
- **判"装没装上"只认工具表与设置页那一节**；**判"闸绿没绿"只认进程退出码**（往 stderr 打提示时，某些管道会误报非零）。

## 11. 术语对照（面板 ↔ 代码）

| 面板说 | 代码里是 |
|---|---|
| 生效中／已关／待配置／降级运行／不可用／未实现 | `state: on / off / waiting / degraded / unavailable / planned` |
| 仅用户可切／由模型执行／双方可切 | `controller: user / llm / both` |
| 谁定的：用户·理由·时间 | 开关账最新行的 `by / reason / ts` |
| 前置步骤（✓ 已做／○ 待办·谁做） | `STEPS` ＋ 步骤探针 |
| 缺依赖（硬／可降级） | `DEPS` ＋ 依赖探针 |
| 纳管 N 个 `.md`／被挡 M 个／这条规则挡了几 | `surface.totals.managed/hidden`、`roots[].matched/excluded/byRule`、`excludes[].hits` |
| 接管／解除接管 | 一行 `lock: true / false` |
| 来源：profile 基线·此处不可删 | `roots[].source === 'profile'`、`removable: false` |
| Jev 判路问句文档（②的输入、⑤要同步、⑥要体检） | 每行 `id`＋`criteria`＋`hint`；本仓库**尚无实现**（亮起功能未搬入） |
| 指针图 / light / check 各是什么 | `lib/graph.js`：`build` 扫 .md → `<dataDir>/graph.json`；`light` 解析起点→BFS→带 reason 清单；`check` 盲区清单 |
| 「精准」「变体」两种命中 | `resolveStarts()` 两级：精准＝条目号/精确同名/归一相等/触发行/标题子串；变体＝归一子串/删一字/词相似度≥0.8，**输出写明用了哪级** |
| 图"该重建" | `graph.stale`＝水位超 `graphStaleHours` 或 `changed>0`（建图后又有文件改动） |
| 判路用的判定模型 | Jev（TypeSafe System One 一类快速结构化判定），设计上可插拔：`jev`｜宿主模型｜本地词法 |
