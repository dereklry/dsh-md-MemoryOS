# OS 使用流程（人这一侧怎么转）

> 面向使用者：装上之后**每天怎么用**、什么时候该动面板、什么时候该让模型动手、坏了先看哪里。
> 你不需要读代码；要读代码看 `DESIGN.md`，给模型看的规则在 `AGENT-GUIDE.md`。

---

## 0. 三条流程，一张图

```
    ┌──────────── 建立（一次性，增量补充）────────────┐
    │  把 md 放进来：骨架 + 条目 + 索引 + 资料表        │  ← 建档器官负责（本版本未上线）
    └───────────────────────┬───────────────────────┘
                            │ 内容进得来
    ┌───────────────────────▼───────────────────────┐
    │  使用（每回合）：亮出相关资料 → 检索 → 出决策材料 │  ← 亮起/检索器官（本版本未上线）
    └───────────────────────┬───────────────────────┘
                            │ 用得越多，缺口越清楚
    ┌───────────────────────▼───────────────────────┐
    │  维护（周期性）：重建图 + 体检 → 盲区变候选 → 你确认 │  ← 候选/维护器官（本版本未上线）
    └───────────────────────┬───────────────────────┘
                            └── 补回「建立」层，闭环
```

**本版本（v0.1.0）已经能用的**：控制面板、状态与依赖体检、开关账本（谁切的、为什么、可追责）、语义引擎这类"配置型功能"的启用流程、模型侧三个工具。
**还没搬进来的**：建档、检索、亮起、候选、定时维护——它们在面板上显示为**未实现**（灰显、没有按钮），别期待其行为。

## 1. 首次启动（十分钟内）

1. **装**：把本包列进 profile 的 `bundles`（或用插件管理器安装），改配置（见 §2），**重启 DSH**。插件不能自己重启自己。
2. **认面板**：设置 → 侧栏出现「**记忆系统**」。顶部四个页签：功能开关 / 概览 / 依赖与路径 / 账本。
3. **看概览**：新装未改配置时徽章应是 `生效中 3`（面板、体检、开关账本）＋ `已关 1`（语义引擎出厂默认关，等 §4 流程接上）＋ `未实现 5`（还没搬进来的器官）。若出现 `不可用`，去「依赖与路径」页看缺什么。
4. **填记忆根**：这是最重要的一步。**没有记忆根，后面所有器官都是空转**。在 profile 里给 `memoryRoot`（多个用 `;` 分隔），重启后「依赖与路径」页该格变绿。
5. **（可选）接语义引擎**：走 §4 那条流程。**现在接上的意义是"等器官上线即可用"**——本版本还没有检索／亮起功能，所以不接也不会少什么；等亮起／候选等器官搬进来后，没接的会在面板显示「待配置」。
6. **让模型认路**：把 `AGENT-GUIDE.md` §7 那个小指令块粘进你的 `AGENTS.md` / preset，模型才会主动用这三个工具，而不是凭记忆猜。

**验收判据（别信日志）**：宿主工具表里出现 `memoryos_status`、`memoryos_switch`、`memoryos_setup`；设置页有「记忆系统」那一节；两页签都能刷出数据。

## 2. 配置：只有 profile 一处

在 profile 的 `cordis.patch.yml` 里本包那一行下面改（**全部可缺省**，留空＝走发现链）：

| 你想干什么 | 改哪个键 |
|---|---|
| 指定要管理的 md 目录（必做） | `memoryRoot` |
| 换账本落点 | `dataDir` |
| 指定 Python（读面纯标准库，系统 Python 就够） | `pythonBin` 或 `kernelRepo` |
| 改测通上游与超时 | `baseUrl` / `model` / `probeTimeoutMs` |
| 测通多久算过期（过期→待配置） | `setupFreshDays`（默认 7） |
| 图水位几天内算新鲜 | `graphStaleDays`（默认 7） |
| **禁止模型改开关** | `llmCanSwitch: false` |
| **禁止模型代存 Key** | `modelCanSaveKey: false` |
| 给某功能改出厂默认 | `defaults:` 下对应键 |
| 允许把 Key 写进 git 仓（不建议） | `allowKeyInRepo: true` |

优先级记一句话：**面板/工具切的最先 > profile 默认 > 出厂默认**。想永久改就改 profile；临时改就在面板上点（会落账）。

## 3. 日常：三种动作，各在哪做

| 你想… | 去哪 | 会发生什么 |
|---|---|---|
| 看现在什么在跑、为什么没跑 | 设置 → 记忆系统 → 功能开关 | 每行显示状态、谁能切、谁定的（＋理由、时间）、成本、缺哪个依赖、差哪一步 |
| 关掉某功能（比如嫌某项每回合花钱） | 同一行点「关」 | 追加一行账，**热生效不重启**；概览统计立刻变 |
| 让模型去办需要动作的启用（测通、存 Key） | 在对话里让它办 | 它调 `memoryos_setup`；做完状态自动从「待配置」变「生效中」，面板「账本」页留下它做过的动作与理由 |
| 某功能被模型反复开关，你想收权 | 该行点「接管」 | 写一行 `lock`；模型再动会被拒（理由回给它）。点「解除接管」还权 |

**「接管」是这页最重要的安全阀**：默认某些功能交给模型执行，但你随时可以说"这件事以后我定"。

## 4. 配置型功能：面板为什么没有开关（以及正确的启用姿势）

有些功能的"打开"不是一下子的事。以**语义引擎**为例：

```
① Jev Key 到位        —— 只有你能做（或你明确委托模型代存）
② API 测通             —— 模型做：真发一次极小请求
③ 生效                  —— 前两步都完成，状态才会变绿
```

所以这类功能在面板上**没有开关**，只有状态和待办清单——写清还差哪一步、这一步归谁。你可以点「接管」把它锁成手动。

**为什么这么绕**：没测通就显示"生效中"是骗人——它会每回合白烧账却什么都没干。

启用操作（在对话里说一句就够）："把语义引擎接上，Key 我放好了，你测一次通就打开。" 模型会按 `where-key → probe → switch on` 走完并复核状态。

## 5. 关于 Key（一条建议，一道守卫）

**建议：存进宿主凭据面，ref 用 `JEV_API_KEY`。**

- 它物理上在 `~/.dsh/.credentials.yaml`：**不在任何 git 仓里**（不存在"忘了 ignore 就推上 GitHub"）；
- 在用户目录：**不随 app 升级被覆盖**（升级替换的是安装目录和 profile 组合）；
- 提供方以 0600 ＋原子替换写它；面板问"配了没有"时不必读明文。

**守卫：** 如果退而求其次写文件，而目标路径落在某个 git 工作树里，本插件**直接拒写**（要放须显式开 `allowKeyInRepo`，且面板会标红）。明文 Key 永不进账本、日志或任何返回值，只出现掩码。

旧位置（比如以前随手放在某个仓里的 `jev-key.txt`）插件仍可以只读兼容（`legacyKeyFiles`），但每次都会标警提醒你搬家。

## 6. 维护：怎么知道"这台机器上的记忆系统"健康

- 面板「依赖与路径」页：四个探针（数据面 / 记忆根 / 指针图 / 内核）一眼能看到；缺"硬"依赖会直接把对应功能标成 `不可用`。
- 面板「账本」页：开关账与配置账都在。任何一次改动都能回答"谁、什么时候、为什么"。
- 测通有**时效**（默认 7 天）：过期后语义引擎自动回退成「待配置」，重测一次即可，不用你记着。
- 后续会上线「定时维护」（周期性重建索引 ＋ 体检，把盲区自动变成候选清单）——本版本还是手动阶段，届时面板会多出它的开关。

## 7. 出问题了按这个顺序查

| 症状 | 先查 | 常见原因 |
|---|---|---|
| 设置里没有「记忆系统」 | profile 的 `bundles` 是否含本包；`Tool.listTools` 有没有三个工具 | 没装进 profile；没重启；`files`/`exports` 少一条（装载契约漏项是**静默**的） |
| 面板在但"没有数据" | 该 profile 有没有 webServer（headless 属预期） | 无数据面＝面板读不到，其余功能照常 |
| 某功能 `不可用` | 「依赖与路径」页缺的哪个硬依赖 | 记忆根没填；找不到 Python |
| 某功能 `降级` | 同一页缺的可降级项 | 没 Jev Key（退回本地词法）；指针图过期 |
| 某功能一直 `待配置` | 该行的待办清单写着谁做 | 归你的步骤没做（Key）；归模型的让它 `probe` |
| 面板点了没变化 | 是不是 `未实现`（灰显无按钮） | 器官还没搬进来，不是坏了 |
| 模型说"开不了" | 让它把 `✗ 拒绝：…` 原文念出来 | 仅用户可切／已被你接管／必须写理由——都是设计 |
| 想彻底回到默认 | 删 `<dataDir>/switches.jsonl`（或对应键）再刷新 | 账本是唯一改动来源，删了就回 profile/出厂默认 |

**判"装没装上"只认工具表与设置页那一节，日志说装载了不算。**

## 8. 升级与回滚

- 升级前先看：`Tool.listTools` 记一份当前工具清单、备份 profile 三件（`package.json`/`cordis.patch.yml`/`pnpm-lock.yaml`）。
- 代码回滚＝在本仓 `git revert`；配置回滚＝还原 profile 三件；两本账是纯追加，留着不影响回滚。
- 面板样式跟随宿主主题（light/dark 都验证过）；若某次升级后主题 token 改名，最坏是外观降级，不会白屏。

## 9. 术语对照（面板 ↔ 代码）

| 面板说 | 代码里是 |
|---|---|
| 生效中 / 已关 / 待配置 / 降级运行 / 不可用 / 未实现 | `state: on / off / waiting / degraded / unavailable / planned` |
| 仅用户可切 / 由模型执行 / 双方可切 | `controller: user / llm / both` |
| 谁定的：用户 · 理由 · 时间 | 最新账行的 `by / reason / ts` |
| 前置步骤（○ 待办、✓ 已做） | `STEPS` 与步骤探针 |
| 缺依赖（硬 / 可降级） | `DEPS` 与依赖探针 |
| 接管 / 解除接管 | 写一行 `lock: true / false` |
