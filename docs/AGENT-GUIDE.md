# 给用户 LLM 的使用指引（AGENT GUIDE）

> 本文写给**装了这个插件之后与用户对话的那个模型**：你手上多了三个工具、一本开关账、一个面板。
> 规则很少，但每条都对应一种"模型很容易做、而系统会因此说谎"的行为。
> 想读实现看 `DESIGN.md`；想读理由看 `JUDGMENTS.md`；用户视角的流程在 `WORKFLOW.md`。

---

## 0. 三十秒版

1. 要判断"某功能为什么没生效／该不该建议用户开它"→ 先 `memoryos_status`，**别猜、别说"应该已经开了"**。
2. 只有 `controller` 是 `llm` 或 `both` 且没被用户接管的项你能切；`memoryos_switch` 的 `reason` **必填**，写成给用户看的中文。
3. 配置型功能（`由模型执行`）**没有开关可拨**：正确顺序是 `save-key`（若用户把 Key 交给你）→ `probe` 测通 → 才 `switch on`。**测通失败就别开**，把原因转告用户。
4. 被拒（`✗ 拒绝：…`）时**照实转告**，不要找绕过路径。拒绝原因是给你和用户看的，不是给你规避的。
5. **指针图是你的地图**：`memoryos_graph`。改了资料面或新写了归档 md ⇒ `build` 一次（零账、秒级、幂等）；"这个词落在哪个条目／哪份文件"用 `light`（**默认只给落点清单**）；**落点不是内容**，要细节仍去 `read` 那个文件；要"牵动哪些文件"才加 `expand:true`。
5b. **准备 `git commit` 前跑一次 `memoryos_graph(action='archive-check')`**（归档闸）：它只看"本次未提交的新增"——新档没人引用 ⇒ warn（多半是忘了在索引里加一行）、文件头回指的条目号悬空 ⇒ warn、本轮新条目没人回指 ⇒ info。**只报事实、不改文件**：拿到 warn 自己判断是不是忘了，忘了就补指针；确属一次性别档就在文件头写 `> 归档：免索引（理由）`。
6. **明文 Key 纪律**：不复述、不写进任何文件/账本/日志/回答；对外只出现掩码。用户没明确让你代存时，引导他自己存进设置或 env。
7. 状态是现算的。你上一轮看到的 `生效中` 这一轮可能已变 `降级`——**每轮要用就再读一次**。

## 1. 你多出来的五个工具

| 工具 | 什么时候用 | 参数 |
|---|---|---|
| `memoryos_status` | 想知道全局或单个功能的真实状态、缺哪个依赖、差哪一步、上次是谁切的为什么 | `feature?`（省略＝全量摘要） |
| `memoryos_switch` | 用户同意之后，或功能登记为"模型可切"且你确有需要 | `feature`、`value:'on'|'off'`、`reason`（必填） |
| `memoryos_setup` | 配置型功能的准备动作 | `action:'probe'|'save-key'|'where-key'|'list'`、`reason`（必填）、`feature?`、`key?`、`path?`、`allow_in_repo?` |
| `memoryos_graph` | 建图、按词查**落点**（哪条目/哪文件/哪行）、体检、**提交前归档闸** | `action:'status'|'build'|'light'|'check'|'archive-check'`、`query?`、`expand?`、`depth?`、`max_nodes?`、`reason?`、`file?`、`no_refresh?` |
| `memoryos_surface` | 看或改**资料面**（哪些目录归 OS 管、排掉哪些子目录与文件） | `action:'list'|'add-root'|'drop-root'|'add-exclude'|'drop-exclude'|'preview'`、`path?`、`pattern?`、`reason`（写操作必填） |
| `memoryos_elements` | **元素库**（元素-时间线内核，本地 SQLite）：把一段话抽成"元素＋**带时间戳事件**"入库、按元素拉时间线／快照、标失效、导出 md 镜像 | `action:'status'|'ingest'|'timeline'|'snapshot'|'all'|'expire'|'export'`、`text?`、`element?`、`elements?`、`source?`、`since?`、`limit?`、`fragment?`、`path?` |

读 `memoryos_status` 的典型输出（每行一功能）：

```
- jev-engine「Jev 凭据与通道测通（不含寻路）」＝待配置（由模型执行）｜定法：账本（模型）：Key 已存放｜待办：真发一次极小请求测通（模型执行）
  ｜成本：只有你主动测通时花一次（≈0.5~1.5 秒一次调用）；不常驻、不每回合发
```

看得懂这四段就够了：**状态**（六档）／**谁能操作**／**谁定的＋为什么**／**还差什么、该谁做**。

## 2. 六档状态各自意味着什么、你该做什么

| 状态 | 含义 | 你的动作 |
|---|---|---|
| `生效中` | 开着且依赖齐、步骤做完 | 可以直接用；引用它时说"生效中" |
| `已关` | 明确关着 | **不要自作主张打开**。想知道为什么关：看 `定法` 那一段（多半是用户自己关的，或理由写着成本） |
| `待配置`（waiting） | 该开，但前置动作没做完 ⇒ **它此刻不产生任何效果** | 你能做的是**把步骤做完**（`memoryos_setup`），不是再拨一次开关；做完状态自动变绿 |
| `降级运行`（degraded） | 开着，但缺可降级依赖，效果打折 | 明确告诉用户缺什么、影响什么（面板会写"退回本地词法""只给候选清单"之类），别当作没看见 |
| `不可用`（unavailable） | 开着但缺硬依赖（记忆根没设、找不到内核、无数据面） | 先解决依赖再谈功能；给用户**去哪改**（profile 的 `config.memoryRoot` / `pythonBin`），而不是"它坏了" |
| `未实现`（planned） | 代码还没搬进来 | **绝对不要**说"我把它打开了"。面板不给按钮，工具也会拒你 |

> 六档都是**现算**的（账本最新行 > profile 默认 > 出厂默认，再叠探针）。所以"我记得刚才还是开的"不作数，读一次就清楚了。

## 3. 配置型功能：完整流程照做，不要跳步

以 `jev-engine`（**Jev 凭据与通道测通，不含寻路**）为例，登记为 `由模型执行`，两步前置：

```
① Jev Key 到位      —— 该谁做：用户（env / 设置里的凭据面），或者他明确交给你代存
② API 测通          —— 该谁做：模型（你）：memoryos_setup(action='probe', reason='…')
        ↓ 两步都完成，状态才会从「待配置」变「生效中」
```

正确顺序（严格按此，闸与账本都按此校验）：

1. `memoryos_setup(action='where-key', reason='确认 Key 在哪')` —— 先看有没有。
2. 没有 Key：引导用户自己存（设置 → 凭据面 `ref=JEV_API_KEY`，或写 env）。**只有他明确把 Key 交给你代存时**才 `action='save-key'` 带 `key=…`。
3. `action='probe'` 真发一次测通。**成功才继续**；失败就把 `note` 里的原因原样转告（例如 `HTTP 401`、`返回不是 JSON`、`超时 6000ms`）。
4. 测通后把状态标成就绪：`memoryos_switch(feature='jev-engine', value='on', reason='已测通，延迟 812ms')`——**这一行只代表"通道就绪"，不代表多出任何查询能力**（本包没有语义寻路）。
5. 用 `memoryos_status(feature='jev-engine')` 复核状态确实是 `生效中`，再向用户汇报（**汇报时别把它说成"接上语义引擎就能查资料了"**）。

三条禁忌：

- **不要先开后测**（会显示成"待配置"，白占一格还误导用户以为在跑）；
- **不要在测通失败后重试成惯性地循环**（一次失败就报告，让用户决定；测通结果有 `setupFreshDays` 时效，默认 7 天内算新鲜，过期会自己回退成"待配置"，届时重测一次即可）；
- **不要把手动"接管"当故障绕过**。用户接管＝他要说说了算，你被拒是设计。请他解除接管，别找别的口子。

## 4. 资料面（管理范围）：改它是重操作

你能用 `memoryos_surface` 看和改"哪些目录归 OS 管、排掉哪些子目录与文件"。四条纪律：

1. **先看再动**：`action='list'` 会给你每根纳管多少 `.md`、被哪条规则挡了几个、样本路径。范围对不对，看一眼就知道，不用猜。
2. **加排除前先 `preview`**：`action='preview', pattern='notes/drafts/'` 会告诉你这条会挡掉多少个文件、举例是哪几个。写系统**拒绝落一条"一个都挡不到"的规则**——因为那通常意味着路径写错了，而"以为排除了"比"没排除"坏得多。
3. **别顺手大范围排除**：`*`、`**`、去掉通配符不足 3 字符的规则会被直接拒。要挡就说到具体：`notes/drafts/`（子树）、`todo.md`（任意层级同名文件）、`*.draft.md`（命名模式）、`archive/**`（跨层子树）。
4. **两条你不能改的事实**：`profile` 的 `config.memoryRoot` 是**只读基线**（面板和你都删不掉，要改让用户改 profile 并重启）；文件类型本版本**固定 `.md`**，别答应用户"能管 txt/代码文件"。

用户说"这个目录别提它"、"那堆草稿不算资料"、"XX 文件夹别扫"——这就是你该动资料面的时刻；动完把 `✓` 那行的话转述给他（含"挡了几个"）。
## 4.5 指针图：四个动作的正确用法

- `status`：先看水位（多久前建的、建完后又改了几份）。**别说"我查过了"，如果图是三天前的。**
- `build`：零账、秒级、幂等。范围来自资料面（profile 基线 ∪ 面板增量），排除规则同样生效。命中 `graphMaxFiles` 会明说"图不完整"——那句话要转告用户，别吞。
- `light`：**默认只回"落点清单"**（2026-10-02 起）——每行＝`文件` 〔条目体·编号／文件／名字〕 L行号 · 短标题，**跳过目录直达"这个词落在哪"**（上限 12 条，超出会写"另 N 处"）。**命中的是条目时，下面紧跟一行「专档」**（`〔专档·回指 XX〕`＋回指行原文）——那是这个条目的**证据全文**所在文件，往往才是你真正要读的那份；再下面可能有一行"另有 N 个文件回指本条目"（只报计数，别把它当清单）。**它不是内容**：要细节 `read` 那个文件（带 offset）。**要邻域地图**（谁指谁＋reason＋建议读）＝加 `expand:true`，那是"这个话题牵动哪些文件"的问题，不是默认答案。用了**变体**档命中（归一子串／删一字／词相似度）必须照原话披露 ⇒ 用户以为你精准命中、其实靠猜，是最坏的沉默。
  **过泛时它只回一个数——照实转述，别追问、别自己补细节**（2026-10-02 口径）：`过泛：\`X\` 命中 N 个起点（闸＝8）` 或 `## 命中过多（N 行 / M 个文件）` ⇒ 就告诉用户"这个词太泛，换个更具体的词"，**不要**去 `read` 一堆文件替它展开（那等于把上下文烧在噪声上：维护者语料上 `light DSH` 曾是 74.7K 字）。想按需要语义找，走 `find`（未实现）/`jev-engine`。
  **零命中时它会自动做"域内正文全文扫描"**（2026-10-02 移植）：报"这个词在哪个文件的哪一行字面出现过"，命中落在已登记条目体里还会给 `〔条目体·编号〕`（可接着 `light <编号>`）。三条纪律照说：**只报字面出现过、不代表这就是答案**（同词不同题是常态，定论要 `read` 落原文）；命中过多时它只说"疑似结构词"并给计数，**别硬替它列**；输出说"**已扫 N 份、零命中**"时，就照实告诉用户"这个词在管理范围内的正文里没出现过"，并念出它给的三种可能（被排除目录／不在 `.md` 里／跨行断词）——**别把"空手"讲成"没有这份资料"**。
- `check`：盲区清单（缺触发行／没人引用的条目／重复条目号／超大文件）。这些**都不报错**，只有 `check` 会暴露；收尾跑一次比事后 debug 便宜。
- `archive-check`：**提交前**跑（用户说"写完了／准备提交／这次归档"时）。范围是"本次未提交的新增"，三条判据给出的 warn/info **不是命令而是线索**：warn＝多半真忘了（补一行索引或补建条目），info＝可判断项。**别为了让闸变绿而乱加引用**——引用的价值在"以后能从这儿找到它"，凑数等于制造噪声；确属一次性别档，加 `> 归档：免索引（理由）` 并在汇报里说明。

## 5. 权限：你能动什么、不能动什么（判在落盘前，界面不是第二套规则）

| 登记 | 你能不能切 | 说明 |
|---|---|---|
| `仅用户可切`（user） | ❌ | 会得到 `✗ 拒绝：…登记为仅用户可切…`。请用户在面板上切 |
| `由模型执行`（llm） | ✅（未接管时） | 面板**不给他开关**，所以这件事本来就该你做；`reason` 必填 |
| `双方可切`（both） | ✅（未接管时） | 你切完，面板会显示"谁定的：模型 · 理由 · 时间" |

另外两条总闸：`llmCanSwitch=false` ⇒ 你完全不能改开关；`modelCanSaveKey=false` ⇒ 不能代存 Key。**都是合法配置，不是 bug**，遇到就转告用户。

未实现（`impl:'todo'`）一律拒，理由会写"代码尚未实现"。**当前已实现：`panel / health / switch-ledger / surface-admin / jev-engine / graph-search`**；**未实现 3 项**＝`scaffold`（建档）、`mining`（候选）、`maintain`（定时维护）——别向用户承诺它们的效果。
> **⚠ 本包没有语义寻路（2026-10-02 与代码对齐）**：`radar`（每回合自动亮起）与 `find`（按需语义寻路）**已从登记表删除**——本包从未实现它们，所以：**别建议用户开 `radar`，也别声称能调 `find`/语义档**。要"这件事该读哪份资料"，唯一的路是 `memoryos_graph`（词/条目号/文件名 → `light` 落点，零账毫秒；查不到时它会做零命中正文兜底）；**"只有事、没有词"在本包答不了**——如实告诉用户，请用户给个词或指定文件。`jev-engine` 那条**只管凭据与通道测通**（Key → probe），测通≠能查资料。

## 6. Key 与安全（不可协商）

- **家只有一个**：宿主凭据面，ref=`JEV_API_KEY`（物理文件 `~/.dsh/.credentials.yaml`：不在任何 git 工作树内、不随 app 升级覆盖、0600 原子写）。
- **写文件有守卫**：目标若落在某个 `.git` 工作树内 ⇒ 直接拒。被拒就把原因说清（"会进仓、可能被推走"），**不要**为了完成任务去传 `allow_in_repo=true`。真需要，让用户明确要求。
- **明文永不外流**：不进回答、不进账本、不进日志、不进工具返回值（`save-key` 成功只回路径＋掩码）。用户贴了 Key，你复述时也只说掩码形状。
- **别去猜机器上的旧 Key 位置**。要确认在哪，用 `action='where-key'`——它只报来源与掩码；读到仓内遗留位时 `warnings` 会提示搬家，请把这句转告用户（这是有意设计的提醒，不是错误）。

## 7. 说话的方式（面板是用户唯一的窗口）

- 说状态用面板那六个中文词（生效中／已关／待配置／降级／不可用／未实现），别自己造词，用户对着看。
- 每次你动了开关，讲三件事：**动了哪个、为什么、热生效还是要重启**（面板/工具写的账都**热生效不重启**；改代码或改 `impl` 才要重启）。
- 涉及钱的功能先讲成本再问要不要开——`memoryos_status` 的 `成本` 段就是给你引用的一句人话。**本包当前没有任何"每回合花钱"的功能**（`jev-engine` 只在主动测通时花一次）。
- 资料面改过、或新写了归档 md ⇒ **提醒或顺手 `memoryos_graph(action=build)`**：新资料没进图，索引永远看不见它（静默失灵，不报错）。
- 用户准备 `git commit` 前 ⇒ 跑一次 `memoryos_graph(action='archive-check')`，把 warn 原话转述（例："这份新档还没有任何 md 引用它"）并问一句是不是忘了加索引。**别替用户决定"这个不用登记"**；要豁免就让文件头那行写清楚理由。
- 不确定就读一次工具。**"读一次"是零成本的，"猜错并让用户白花钱"不是。**

## 8. 可粘进 AGENTS.md / preset 的最小指令块

```
MemoryOS：功能状态一律以 memoryos_status 为准（现算，别引用记忆里的旧状态）。资料面（管到哪些目录／排掉哪些文件）用 memoryos_surface：先 list 再看，加排除前必须 preview；profile 基线删不掉、类型固定 .md 不许承诺扩展。
指针图用 memoryos_graph：改了资料面或新写归档 md 就 build；light 默认只给落点（哪条目/哪文件/哪行，不是内容），命中级别（精准／变体）照原话转述，要地图才加 `expand:true`；收尾跑一次 check 报盲区；**准备 git commit 前跑一次 archive-check**（只看本次新增：新档没人引用／回指条目号悬空 ⇒ warn，只报事实不改文件，豁免写法 `> 归档：免索引（理由）`）。
元素库用 memoryos_elements：聊到/写下的元素与**带时间戳事件**用 `ingest` 固化（文本里要有 6 位代码，或显式给 `elements`——未知新概念会作为**待确认候选**返回，**别自己建**）；问"某元素过去发生过什么"用 `timeline`／`snapshot`；**没有 API Key 时走规则层**，照实说"抽取＝规则层"，别讲成"AI 抽取的"。它管**结构化事实**，与"这件事该读哪份 md"（走 memoryos_graph）不是一回事。
**别把元素库说成"AI 在理解你的话"**：本包当前**没有接任何 LLM 通道**（`ingest` 返回里的 `llm:false` 就是证据），抽取走的是**规则层**（时间解析 ＋ 元素线索）；将来若接了（`DEEPSEEK_API_KEY` 那条），也只有在 `llm:true` 时才能那么说。任何"用了模型／API"的说法都要与返回值一致——这是本包"不吹牛"的最低要求。
文件头契约：专档开头写 `> 档位：叶子 ｜ 指针条目=AAx`（叶子默认；中枢＝指路文件）；条目写成 `### AA17 <情形>：<动作>` ＋ `- **触发**：` 一行（用户会怎么说）。
只有登记为「由模型执行/双方可切」且未被用户接管的项你能切，且必须写中文 reason。
配置型功能（如 jev-engine）不要拨开关：先 where-key → save-key(仅用户明确委托时) → probe 测通 → 才 switch on；
测通失败就报告原因，不要循环重试，不要先开后测。
被 ✗ 拒绝时照实转告原因，不找绕路；「接管」不是故障。
明文 Key 不进回答/文件/账本/日志；写文件命中 git 工作树被拒时，不要传 allow_in_repo。
```

## 9. 一次典型排障（照着走）

**用户**："资料亮起怎么没弹？"
1. `memoryos_status(feature='radar')` → 看到 `状态＝未实现`（或 `待配置`／`已关`）。
2. `未实现` ⇒ 直说：这个器官还没搬进本版本，别假装它在工作。
   `待配置` ⇒ 读 `待办`：比如"指针图已建（模型执行）"→ 你能做就做完再复核，做不了就说明缺什么。
   `已关` ⇒ 读 `定法`：若是"用户 · 理由：不想花钱"，**不要重新打开**，问一句是否改变主意。
   `降级/不可用` ⇒ 读 `缺依赖`，把"去哪改"（profile `memoryRoot` / `pythonBin`）告诉用户。

**用户**："面板里这一节不见了。"
→ 多半是 `panel` 被关或数据面没起来。查 profile 的 `defaults.panel`；headless/无 webServer 时面板本就无数据（插件其余功能照常）。**别改代码，先看账本和配置。**

**用户**："我给了 Key 了，为什么还说没配？"
→ `memoryos_setup(action='where-key', reason='…')` 看它到底落在哪（env？文件？凭据面？），再 `action='probe'` 实测一次。如果 `warnings` 说 Key 在 git 树内，顺便提醒搬家。

## 10. 你**不该**做的事（一页清单）

- 别为了让功能"看起来在工作"而开未实现项、或跳过测通。
- **别替用户"顺手"改资料内容**；要改先问。也别提醒他"同步资料表/问句表"——**本包没有那种表要维护**（那是语义档的输入，本包没这一档）。
- 别把「接管」当故障绕过；别自行解除接管（`/release` 是用户的手）。
- 别在 `已关` 时自作主张打开——尤其成本类功能。**关掉通常是用户算过账的决定。**
- 别把明文 Key 落到任何地方；别为图方便用 `allow_in_repo`。
- 别连续重试失败的配置动作；一次失败就交回人判断。
- 别引用上一轮的状态快照当事实。
- 别把 `light` 回来的清单当内容直接答（那是落点/地图）；要细节就 `read` 那个文件。
- 别在图过期时凭旧图回答，也别忘了一句"改了资料请重建"。
- 别向用户承诺 `impl:'todo'` 的器官的效果（当前：资料亮起、建档、候选生成、定时维护）。
