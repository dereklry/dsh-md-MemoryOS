# 设计判断（为什么长这样）

本档只记**判断与边界**；用法看 `../README.md`，口径实现看 `lib/features.js`（它是唯一权威）。

## 1. 三层拆分：什么东西能进包

把一套"本机跑通的工作流"变成别人能装的产品，先分清三层：

| 层 | 内容 | 处置 |
|---|---|---|
| **机制层** | 工具面、每回合资料亮起、技能随包、开关账本、面板、定时维护 | ✅ 随包分发（本仓就是这一层） |
| **内容层** | 某人的资料表条目、他的条目正文、他的别名表、他的扫描目录与业务台账 | ❌ 绝不随包分发——在别人机器上全是噪声，只能安装后长出来 |
| **自举层** | 让"内容层"从用户真实过程里自己长出来（建档→观测→提议→人确认→落表） | 🆕 待实现；这条才是这类系统真正的门槛 |

**推论**：任何"我把我的模板/词表/例子发给你，你装上就有效果"的方案，都只是在发机制层，效果来自内容层。

## 2. 功能有两类，硬套一个开关会骗人

- **一键可切**：开关本身有意义（关掉真的就不跑）。
- **配置型**：所谓"开启"是一串动作。例：语义引擎＝Key 到位 → 真发一次请求测通 → 才允许置为生效。

第二类**不给开关，给状态**：`待配置 / 降级 / 不可用 / 生效中 / 已关 / 未实现`，外加"还差哪一步、这一步该谁做"。用户保留「接管」这条退路（写 `lock` 行，模型改不动；解除即还权）。

理由很朴素：**把没测通的东西显示成"生效中"不是乐观，是骗人**——它会每回合白烧账却什么都没干。

## 3. 状态一律现算，只有"操作"落盘

存下来的状态必然与事实分叉。所以盘上只有两本 append-only 账：

- `switches.jsonl`＝谁切的（用户/模型）、值、理由、时间、接管标记；
- `setup.jsonl`＝做过哪些配置动作（测通结果与延迟、代存 Key 的落点与掩码）。

其余（依赖探针、步骤就绪、最终状态）每次现算。生效值三层：**账本最新行 > profile 默认 > 登记表出厂默认**。

## 4. 权限判在落盘前，不判在界面上

面板与模型走**同一个** `writeSwitch()`。`controller` 是数据不是装饰：

| controller | 用户 | 模型 |
|---|---|---|
| `user` | 可切 | 拒（并回理由，模型能转告用户） |
| `llm` | 面板不给开关；但可接管/解除 | 可切，**必带 reason** |
| `both` | 可切 | 可切（除非已被用户接管） |

外加两条总闸：`llmCanSwitch`（模型到底能不能改开关）、`modelCanSaveKey`（能不能代存 Key）。

## 5. 秘密只待在一个地方

**Key 的正家＝宿主凭据面**（`~/.dsh/.credentials.yaml`，ref=`JEV_API_KEY`）：不在任何 git 工作树里 ⇒ 不可能被推上 GitHub；在用户目录 ⇒ 不随 app 升级被覆盖；提供方以 0600 + 原子替换 + 文件锁写它。

退到文件时有一条硬守卫：**目标落在某个 `.git` 工作树内就拒写**（除非 profile 里显式 `allowKeyInRepo: true`）。

> 为什么值得写成代码而不是写进文档：靠 `.gitignore` 挡密钥，等于把安全交给"某人记得加那一行"。守卫写死之后，忘记 ignore 这件事**没有后果**。明文 Key 永不进快照、账本、日志、工具返回值——闸里有三条断言专门盯这件事（F1/F3/F5）。

## 6. 装载契约（错过一次就要重看一遍的四条）

浏览器半要能被宿主发现，四条缺一即"设置页没有那一项，且**零日志**"：

1. `dsh.client.platform = "web"`；
2. `exports["./client"]` 指向浏览器文件；
3. `exports["./package.json"]` 必须存在（装载器用 `require.resolve('<pkg>/package.json')` 扫声明，解析失败被**静默 catch**）；
4. `window.__ModuleLoader__.load({ id })` 的 `id` 必须等于包名。

还有两条同源的坑：**webServer 是晚到 Service**（只能 `ctx.inject(['webServer'], …)` 局部等，写进顶层 `inject` 会让 headless profile 整个插件永挂）；**HTTP 前缀必须注册 prefix 兜底回 JSON 404**（否则未知子路径掉进 SPA 回落返回 HTML，前端 `res.json()` 炸，症状是"面板空白无报错"）。

## 7. 闸是这份代码的一部分

`test/load.js` 105 条，全程不联网（`transport` 可注入）。它盯的都不是"函数返回值对不对"，而是**别人踩过的静默失败**：

- 登记表 ↔ 探针 ↔ 面板路径 三方同源（漏一处就是永远显示"探针未实现"或静默 404）；
- 配置型功能的完整生命周期：`off → 模型开＝待配置 → 存 Key → 测通 → 生效中`；
- 接管粘性（跨请求成立）、同值不重记、未知功能名回列可选项；
- 样式合并禁用 `[a,b].reduce(Object.assign)`（索引进 style ⇒ 整块 slot entry 崩）、禁用嵌套花括号误判的逗号表达式、颜色只用主题 token；
- 明文 Key 不出现在账本/日志/返回值。

跑法：`node test/load.js`（或 `ELECTRON_RUN_AS_NODE=1 <DSH 二进制> test/load.js`）。
**判通过只认真实 ExitCode**：往 stderr 打 warn 时，某些 shell 管道会误报非零退出码。

## 8. 路线图（顺序有理由）

1. **检索面**（指针图：词→文件/行，本地零账）——先让它"查得到"。
2. **亮起面**（radar：每回合把匹配的资料亮给模型）——再让它"自己找上门"。
3. **建档**（扫记忆根 → 四层骨架 + 资料表初稿）——没有内容层，前两步是空转。
4. **候选回灌**（查空的词→别名、反复读的文件→资料行，**只出候选，人确认才落表**）。
5. **定时维护**（周期性 build + check，盲区进候选队列）。
6. 面板随各阶段长出来（功能表已经是它的骨架）。

> 第 4 步刻意不做成"自动决定"：这类系统里"替用户判断哪条资料值得留"是最容易翻车的一环。自动出候选、人来批，是保守但能跑的组合。
